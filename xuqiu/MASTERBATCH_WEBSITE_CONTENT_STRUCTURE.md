# 色母粒 B2B 独立站内容结构草案

- 状态：内容结构草案
- 日期：2026-11-03
- 公开主体：GE CHEMICAL & POLYMER GROUP CO., LTD
- 适用范围：英文 B2B 询盘型独立站的内容规划
- 说明：本文不是最终网站 PRD，不确定最终 URL、技术栈或开发任务。

## 1. 文档目的

本文整理色母粒 B2B 独立站的整体内容结构，并区分：

1. 网站未来可以扩展到的完整内容范围；
2. 首版应优先上线的核心页面；
3. 第二版在首版基础上扩展的内容；
4. 现阶段仍需要业务确认、产品证据或公开授权的页面。

本方案按“通过内容、SEO 和产品询盘页面获取海外 B2B 咨询/询盘”理解网站目标，不把首版定位为 B2B 商城或公共技术文件下载站。

## 2. 核心转化路径

网站的主要转化路径为：

```text
买家搜索问题
→ 找到产品页或专业知识内容
→ 判断产品方向是否匹配
→ 提交 RFQ 或技术文件申请
→ 团队人工审核产品和文件范围
→ 通过电子邮件回复
```

技术文件采用“申请表 + 人工审核 + 邮件回复”流程，不提供 TDS、SDS、COA、RoHS 或 FDA 文件的公开下载。

## 3. 内容设计原则

- 一个页面主要解决一个明确的搜索意图。
- 产品页负责说明买方需要准备什么，并承接询盘，不提前承诺固定参数、价格、MOQ 或交期。
- 知识文章负责解释问题和建立信任，并通过内部链接引导到产品页、文件申请页或 RFQ。
- 产品参数只用于具体牌号，并注明对应文件、适用条件和证据边界。
- 合规文件只支持具体测试样品或牌号，不能扩展为整条产品线合规。
- 首版优先上线有证据、接近询盘、能够完整回答用户问题的页面。
- 暂不上线空栏目、占位页或只有关键词而缺少实质内容的页面。
- 公司产能、客户名称、认证、检测和案例等信任信息，在公开前必须经过业务确认和授权。
- 知识库用于通用教育、选型框架和询盘流程，不作为具体产品参数、性能、合规或商业承诺的证据。
- 知识库内容应按照搜索意图改写为英文网站页面，不把 12 课原文直接复制或逐字翻译成网站内容。

## 5. 整体结构、首版和第二版的关系

整体内容结构是网站的目标地图。首版和第二版不是两套不同结构，而是同一套结构的分阶段落地。

| 整体结构栏目 | 首版处理方式 | 第二版扩展方式 |
|---|---|---|
| 首页 | 上线基础首页，说明公司、产品、服务流程和询盘入口 | 根据询盘结果增加案例、产品证据和更完整的内容入口 |
| 产品与询盘 | 只上线黑色、白色、彩色三个询盘指南 | 增加已确认的具体牌号和更多产品线 |
| 应用场景 | 暂不作为主要导航栏目，只保留少量相关内容 | 增加薄膜、注塑、再生塑料、挤出和吹膜等应用页 |
| 技术文件 | 上线文件申请页和少量文件说明 | 扩展为 TDS、SDS、COA、RoHS、FDA 等文件主题集群 |
| 资源中心 | 先发布基础文章和 FAQ | 扩展为选型、质量、采购和应用的完整内容集群 |
| 术语与常见问答 | 合并为 FAQ 或少量内容 | 建立独立术语库和完整问答中心 |
| 关于我们 | 将公司和质量信息合并为 About / Quality 页面 | 拆分生产、检测、包装、出口和服务流程 |
| 客户案例 | 除已获授权材料外暂不发布 | 增加已授权案例、客户评价和项目经验 |
| 国家市场页面 | 暂不制作 | 在具备当地搜索、买家和进口商证据后扩展 |
| 隐私政策 | 首版必须上线 | 根据表单、分析工具和 Cookie 使用情况更新 |

首版不是把整体结构中的每个栏目都做成简版，而是优先打通“搜索—了解产品—提交询盘—人工回复”的完整闭环。

#### 6.1.3 P0 页面大纲

##### Home

页面任务：让海外买家快速确认业务范围、三类母粒入口和询盘流程。

首版 `front-page` 模板结构：

1. Hero：说明面向塑料加工应用审核 black、white、color masterbatch 询盘。
2. 三类母粒入口：Black、White、Color 三张产品卡片，每张卡片说明买方需要准备的信息。
3. 应用场景入口：薄膜与包装、注塑、挤出、再生塑料。
4. 询盘审核流程：提交应用 → 描述目标 → 核对牌号和文件范围 → 邮件回复。
5. 技术文件说明：按具体牌号、应用、国家和用途人工审核。
6. About 摘要：使用已批准的 masterbatch supplier 定位、产品范围和三张素材库图片。
7. 资源与 FAQ：基础知识、选型应用、RFQ 与技术文件三个内容方向，并回答产品范围、RFQ 准备和文件审核问题。
8. 最终 CTA：RFQ 和技术文件申请。

不得加入：未确认的产能、生产线数量、市场数量、客户名称、实验室能力或全系列认证。

##### Masterbatch Guides

页面任务：帮助买家判断应该进入黑色、白色还是彩色母粒指南。

建议结构：

1. H1：`Masterbatch Guides for Black, White and Color Requirements`。
2. 三类买家和应用场景概览。
3. Black / White / Color 三张指南卡片。
4. 选择对照表：买家的主要问题、需要准备的资料、对应指南。
5. 文件审核说明和 RFQ CTA。

此页不是产品归档页，不展示虚构价格、MOQ、库存或具体牌号参数。

##### 三个产品指南

黑色、白色和彩色页面共用 `page-product-guide`，但保持各自不同的搜索意图、RFQ 字段和证据边界：

| 页面 | 主要搜索意图 | 必须覆盖的买方输入 | 主要内链 |
|---|---|---|---|
| Black | 黑度、遮盖、分散、树脂、工艺、替换和文件需求 | 树脂、工艺、应用、黑度、当前问题、现用牌号、数量、目的港 | Guides、RFQ Checklist、技术文件申请 |
| White | 白度、遮盖、TiO2、树脂、应用和文件需求 | 树脂、工艺、应用、白度/遮盖、TiO2 context、现用牌号、数量 | Guides、RFQ Checklist、技术文件申请 |
| Color | 颜色参考、树脂、工艺、色差预期和打样沟通 | 树脂、工艺、最终制品、颜色参考类型、容差期望、现用牌号 | Guides、RFQ Checklist、技术文件申请 |

三页统一保留：证据边界、文件人工审核、一个主 RFQ CTA 和一个技术文件次 CTA。

##### Request a Quote

页面任务：集中收集完整 RFQ，而不是重复解释三类产品。

建议结构：

1. H1 和简短说明。
2. 表单前置说明：需要哪些信息、资料如何审核。
3. 共享 `rfq_document_request` 表单，RFQ 模式。
4. 产品兴趣通过查询参数预填：black、white 或 color。
5. 成功状态只说明已收到并人工审核，不承诺价格、MOQ、交期或文件可用。

##### Request Technical Documents

页面任务：收集文件审核请求，不提供公开文件下载。

建议结构：

1. H1：`Request Masterbatch Technical Documents`。
2. TDS、SDS/MSDS、COA 和合规文件的基础说明。
3. 文件按产品、牌号、应用、国家和用途审核的原因。
4. 文档类型和 Document Purpose 条件字段。
5. 人工审核和邮件回复说明。
6. 成功状态与隐私提示。

##### About / Quality

页面任务：建立主体和流程信任，不把内部公司资料原文直接发布。

建议结构：

1. 已批准的公开主体和公司定位。
2. 主营黑色、白色和彩色母粒询盘方向。
3. 需求核对、牌号审核、样品讨论和文件申请的流程。
4. 经证明和授权的生产、检测、包装或出口内容；没有证明则删除。
5. 不展示个人电话、未授权邮箱、客户品牌或未确认认证。

##### Privacy Policy

页面任务：说明表单和邮件处理的数据范围。

最低覆盖：

- 收集字段及用途；
- 数据保存位置和访问权限；
- 保留期限；
- 第三方邮件、反垃圾、分析或 Cookie 工具；
- 用户请求修改或删除信息的方式。

表单上线前，隐私政策必须与真实实现一致。

4. 用同一模板创建白色和彩色指南。

6. 审核 About / Quality，再创建 Home。

8. 检查所有页面、内链、Canonical、Sitemap、表单和移动端表现。

首版内容完成的判断不是“页面已经创建”，而是：

- 9 个 P0 页面均有实质内容；
- 三类指南的证据边界和表单上下文正确；
- 所有导航、CTA 和相关链接返回 200；
- 表单能够提交并由人工审核；
- 隐私政策与表单实现一致；
- 所有页面保持单一 H1、唯一 Title 和 Description；
- 没有非 GE 公开主体、未批准参数或全系列合规声明。

### 6.2 黑色母粒询盘指南

页面应覆盖：

- 薄膜、塑料袋、注塑和再生塑料等买方场景；
- 基础树脂、加工方式、黑度、分散要求和当前问题；
- 炭黑含量、载体和 MFI 等参数为什么必须对应具体牌号；
- 当前牌号、替换需求和原供应商信息；

## 11. 内容证据与声明边界

### 黑色母粒

- 先根据搜索意图定页面，再从知识库选择相关内容，不把多门课程合并成一个超长页面。
- 每个技术结论至少保留适用产品、测试条件、证据范围和下一步确认动作。
- 知识库中的内部证据编号和待确认编号可以保留在内容规划中，正式英文页面只保留必要、简洁的客户提示。
- 产品页以询盘和核对为主，不把知识库中的通用解释扩写成具体产品性能。
- 质量文章只写“可能原因”和“核查步骤”，不写远程诊断或唯一根因。
- 文件文章只写申请、审核和邮件回复，不出现公开下载或即时证书。
- 每篇文章安排明确的内部链接：资源文章 → 产品询盘指南 → RFQ 或技术文件申请。

### 15.6 知识库不能替代的资料

以下内容不能只从知识库生成，仍须补充证据或业务确认：

- 具体牌号、技术参数和适用范围；
- 添加比例、MOQ、价格、交期、付款和包装政策；
- 样品、机台试验和量产确认结果；
- FDA、RoHS、REACH、食品接触或其他法规结论；
- 公司生产线、年产能、实验室和市场覆盖；
- 客户名称、评价和案例；
- 品牌 Logo、图片视频版权和人物肖像授权。
